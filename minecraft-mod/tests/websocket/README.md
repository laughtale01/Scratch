# WebSocket の受け口の試験

`src/main/java/com/github/minecraftedu/network/SimpleWebSocketServer.java` を、Minecraft を起動せずに確かめる試験です。
Minecraft の部品（`MinecraftServer`・`CommandExecutor`・`MinecraftWebSocketHandler`・ロガー）は `stubs/` の偽物に差し替え、
本物の `SimpleWebSocketServer.java` をそのままコンパイルして動かし、Python から接続を送ります。

## 流し方

```bash
cd minecraft-mod
mise exec -- bash tests/websocket/run.sh
```

- Java 17（`mise.toml` の temurin-17）と python3 が要ります。
- 試験用のポートは 24711 です（本物の MOD の 14711 とぶつからないように）。変えるときは `WS_TEST_PORT=24800` を付けます。
- 2 分ほどかかります（時間切れの確かめで数秒ずつ待つのと、ログの間引きの確かめで 60 秒待つため）。
- MOD のビルド（`./gradlew build`）には含まれません。
- はじめに `tests/data/check_vertical_slab_data.py` も流し、縦スラブの名前が ModBlocks・ModItems・loot table・タグでそろっているかを確かめます（食い違いがあれば、そこで止まります）。

## 確かめていること

- つないでよいサイト（Origin）: `https://laughtale01.github.io` と `http://localhost:8000`・`http://127.0.0.1:8000` だけ。無い・ほかのサイトは 403
- 自分の PC 以外（LAN のアドレス）からの接続はすぐ切る（Mac のときだけ確かめる）。IPv6 の `::1` からはつながる
- ヘッダーの上限（1 行 8KB・100 行）ですぐ切る。ハンドシェイクの締め切り（受け持ちが始まってから 2 秒。少しずつ送っても延びない）
- ハンドシェイクと最初のフレームが 1 回で届いても、フレームを取りこぼさない
- マスクの無いフレーム、1MB を超えるフレーム、125 バイトを超える制御フレームは切る。Ping には正しい長さの Pong を返す
- 同時接続は 8 本まで（ハンドシェイクが済んだ接続を数え、9 本目は 503 で断る）。断った接続・切れた接続のあとも枠が戻り、余計にも増えない
- ハンドシェイクの前の接続（ブラウザが前もって開く接続など）は 8 本の枠に数えない。別に 64 本まで数え、超えたら一番古いものを切る（何も送らない接続が 8 本・70 本あっても、Scratch はつながる）。押し出しのログは WARN 1 行だけで、押し出された側は何も出さない（ほかの断り方のログがまだ間引かれていない、いちばん初めに確かめる）
- ログ: 受け取った全文を出さない、断った Origin は見える ASCII 以外を `?` にして 100 文字ほどに切る、断った接続のログは理由の種類ごとに 60 秒に 1 行まで（鍵のないリクエスト・長い URL・ハンドシェイクの途中で切られた接続・時間切れも。くり返してもログ全体が DEBUG も含めて増えないことを数える。60 秒たつと間に断った数を書いて 1 行出る）、つながった接続が切れたら info で出す
- 決まりに合わないフレーム（マスクなし・大きすぎる）のログは、くり返しても 1 行だけ。つないだあとに乱暴に切られても ERROR を出さない

## 確かめていないこと（試験の外）

- `MinecraftWebSocketHandler` と `CommandExecutor` は偽物なので、命令の中身（断ったときのチャットやログ）はこの試験では確かめていない（受け取った全文がログに出ないことは、本物の `SimpleWebSocketServer` で、この試験が確かめている）
- 受付のループで Error が起きたときの片付け（ハンドシェイクの前の一覧から外して閉じる）と、失敗が続いたときの 100ms の待ち
- 締め切りを過ぎても、もう届いているヘッダーは読み切ること（読む途中で Minecraft が止まっても切らないため。締め切りの時点でバイトがたまっている場面を、試験で作っていない）
- 押し出した接続のスレッドが、閉じたとたんにすぐ終わること（Mac の試験では、相手側で切れたことだけを見ている。Windows ではまだ確かめていない）
- 受け持つスレッドが上限（ハンドシェイクの前 64 ＋ つないだ 8 ＋ 8）でいっぱいのときに、空くのを 1 秒まで待つ道（待っても空かなければ「handler threads busy」で断る）。押し出しとハンドシェイクの完了がぶつかったときと、枠を取ったあとに 101 を書くのに失敗したときの片付け（コードを読んで確かめた。試験で順番を作るには、本物のコードの途中で止める仕掛けが要るため）
- 停止（stop）の途中に来た接続の片付け
- Windows での動き（この試験は Mac で作った）
- `CommandExecutor` の中身（座標と範囲の上限、名前の打ちまちがい、キーや params が無いとき、消した入口（query の受け口・getBlock の命令）が残っていないこと、チャットの長さと見えない文字、断ったときのチャットとその間引き）。下の手順で、本物の MOD で確かめる
- 下の手順でも出せないチャット: 「MOD の なかで まちがいが おきました（せんせいに しらせてね）」（MOD の不具合のときだけ）、「いま まわりを きれいにしている とちゅうです。おわるまで まってね」（「周りをきれいにする」を動かす必要がある）、「いまは いきものを だせない せっていです」（先生が `/entityspawn deny` にしたとき）
- MOD の受け口を開けなかったときの知らせ。下の「ポートが使われているときの知らせを確かめる手順」で確かめる
- 世界を変える命令の列（大きな仕事を少しずつ置く作り）のうち、下の手順で確かめるのは、順番（大きく埋めた直後に置いたブロックが残る、置いた直後に調べると置いたブロックが答えられる、テレポートのあとの相対座標）と、区画の境をまたぐ範囲が抜けもはみ出しも無く置かれることだけ。列が混んでいるときの読む命令（列に並ばずに今の様子を答える）も確かめない。Minecraft が止まらないこと（遠くのチャンクで止まらないことは、下の「遠くのチャンクで Minecraft が止まらないことを確かめる手順」で手で確かめる）、列が混んでいるときの知らせ（「いま たくさん つくっている とちゅうです…」）、ポーズ中も置かれること、「周りをきれいにする」のすぐあとに置いたブロックが残ることは確かめない。止まらないことは、流している間にゲームの画面が固まらないかと、`latest.log` に `Can't keep up` が出ていないかを見る（前のビルドの MOD は版の数字が同じだが、はじめの「見ているブロック」の答えに queued が無いので、そこで止まる）

## 本物の MOD で上限と、断ったときのチャットを確かめる手順

**必ず新しく作った試し用のワールドで行ってください。授業で使うワールド（生徒の作品があるワールド）では行わないでください。**
「周りをきれいにする」などを間違えて動かすと、作品が消えて元に戻せません。

Scratch（gui.js）は体積を先に確かめて断るので、Scratch のブロックからでは MOD 側の確かめまで届かない場合があります。
そのため、命令を MOD へ直接送るスクリプト `probe_fill.py` で確かめます。

1. MOD を新しくビルドして入れ直す（古い MOD のままだと、古い MOD を確かめてしまう）
   - mods フォルダに前の jar（`minecraftedu-mod-0.1.0-1.20.1.jar` や `minecraftedu-mod-0.1.0.jar` など）があれば、先に外す（同じ MOD が 2 つあると、正しく読み込めない）

   ```bash
   cd minecraft-mod
   ./gradlew build
   # build/libs/ にできた jar（minecraftedu-mod-0.2.0-1.20.1.jar。版は build.gradle の version）を Minecraft の mods フォルダにコピーし、Minecraft を起動し直す
   ```

2. Minecraft で、新しく作った試し用の**スーパーフラット**のワールドを開く（ふつうのワールドでは流さない。山の頂上などがあると、空気で削れる）
   - **オーバーワールド**（ネザーやエンドではない）にいて、**クリエイティブ**にしておく（y=-60 へテレポートするので、ネザーでは奈落に落ちる。また古い MOD に流すと、ワールドの外へテレポートしてしまうことがあるため）
   - 生き物を出すのを止めていたら、チャットで `/entityspawn allow` と打って許可しておく（止めたままだと、生き物の名前の打ちまちがいの件が「いきものを だせない せってい」になって NG で止まる）
   - Scratch のタブなど、ほかに MOD へつないでいるものは閉じておく（ほかの接続が大きく埋め続けていると、MOD の列が空かず、前の命令が終わるのを待つ確かめが 60 秒で NG になる。NG のあとの片づけでも列が空くのを待つので、さらに少しかかる。待ちきれないときは Ctrl+C を押すと、片づけをやめて手で消す案内を出す）
3. Minecraft と同じ PC の別の端末で、次を実行する（試し用のワールドか聞かれるので、`yes` と入力する。Windows では `python3` の代わりに `py` を使う）

   ```bash
   cd minecraft-mod
   python3 -I tests/websocket/probe_fill.py
   ```

   - このスクリプトは、ランチャーで起動した Minecraft（mods フォルダに jar を入れたもの）に向けて流す。開発用の起動（`./gradlew runClient`）では MOD の版が `0.0NONE` になるので、版の確かめで止まる

4. 画面に、それぞれの命令の結果（ok / NG）が出る。チャットを確かめる命令（断られる命令、入れ物の件、チャットの件）のたびにスクリプトが止まるので、ゲームのチャットで「[probe] N 件目」の行のすぐ下に下の表の文が出たかを見て、出たら `y` と入力する（同じ文が続くので、番号の行で前の命令の文と見分ける）
   - はじめに、接続の返事で MOD の版（0.2.0…）と最大の接続数（8）を確かめる。続けて「見ているブロック」の答えに queued があるか（世界を変える命令の列が入ったビルドか。前のビルドは版の数字が同じなので、版では見分けられない）を確かめる。違えば、ワールドに命令を送る前に止まる
   - 大きな「ブロックで埋める」のあとは、Minecraft が置き終わるまでチャットに出ないことがある。出るまで待ってから答える
   - 途中でプレイヤーを x=1000, y=-60, z=0 へテレポートする（相対座標の確かめのため）。終わったら（NG で止まったときも）元の場所へ戻す
   - 最後に、空の上（x=-43〜-37, y=257〜264, z=-43〜-37）に石の箱を作ってプレイヤーを中へテレポートし、「見ているブロック」が壁に当たるかを確かめる。終わったら前の場所へ戻してから箱を消す
   - はじめに元の場所の座標を表示する。ゲームが落ちたなどで戻せなかったときは「/tp @s x y z で戻ってください」と表示するので、そのとおりに打って戻る
   - 返事だけでは断った理由が分からない（ほかの理由で断られても同じ返事になる）ので、チャットの文で確かめる
   - 問いの文が「=」で始まるときは、番号の行のすぐ下の行が、ちょうどその文（それより長くも短くもない）かを見る（チャットの長さの確かめ）
   - 期待と違う結果が 1 件でも出たら、そこで止まる。NG のときは、まず mods フォルダの jar が新しくビルドしたもの 1 つだけかを確かめる
5. 最後に、失敗のチャットの間引きを 8 件確かめる。「[probe] 間引き N」と「[probe] 間引き N おわり」の 2 つの行のあいだに、下の表の文が上から順に、それだけ出たかを見て、そうなら `y` と入力する

| 送る命令（番号の行をはさまずに続けて送る） | 2 つの行のあいだに出るはずの文 |
|---|---|
| ブロックを置く、x が回り込む数を 5 回 | 「ばしょがワールドの外です」だけ |
| ブロックを置く（x が回り込む数）と、ブロックで埋める（x が回り込む数）を、かわりばんこに 3 回ずつ | 「ばしょがワールドの外です」「はんいがワールドの外です」だけ |

| 入れ物が無い所にアイテムを入れる、ふつうのチャット、もう 1 回（返事を待たずに 3 つ続けて送り、あとで返事をまとめて受け取る） | 「そこに いれものが ありません」「probe ふつうの チャット」「そこに いれものが ありません」（出る順がそのまま） |

## ログの確かめ（任意）

`probe_fill.py` のあとに、Minecraft のログで、失敗のログが増えすぎていないかを確かめる（Mac は `~/Library/Application Support/minecraft/logs/`、Windows は `%APPDATA%\.minecraft\logs\`）。

- `latest.log` の `WARN` の行が、失敗の種類ごとに 1 行だけ（60 秒のあいだ）であること。2 回目からは `debug.log` にだけ出る
- 「MOD が知らない命令」と「ブロックを調べる（getBlock）の命令」の件は同じ間引きに入り、`Unknown command: noSuchCommand` の WARN 1 行であること（ただし 60 秒より長くかけて答えたときは、`Unknown command: getBlock` の行がもう 1 行出てよい）
- 「params が無い」の件が `Command without params: clearArea` の WARN 1 行であること。「中心のキーが無い」の件が `Bad command parameters: clearArea (MissingParameterException: …)` の WARN 1 行であること。「x が無い」の件が `Bad command parameters: teleport (MissingParameterException: missing parameter)` の WARN 1 行であること
- 「知らないプロパティが 2 つ」の件が、`Unknown property '…' for block air (2 unknown properties)` の 1 行にまとまっていること（DEBUG も含めて、1 回の命令で 1 行）
- 「座標が数でない」と「ブロックの名前が無い」の件が、`Bad command parameters: setBlock (UnsupportedOperationException: …)` と `Bad command parameters: setBlock (NullPointerException: …)` の WARN 1 行ずつで、スタックトレース（`at com.github…` の行）が付いていないこと（同じ命令でも、例外の種類ごとに 1 行）
- 「出さない一覧のもの」「Minecraft でも出せないもの」「弾そのもの（雪玉）」の 3 件が、`Blocked entity type: minecraft:dragon_fireball` の WARN 1 行であること（3 件は同じ間引きに入る。ただし前の WARN から 60 秒より長くたってから答えたときは、`Blocked entity type: minecraft:player` や `Blocked entity type: minecraft:snowball` の行が出てよい。多くて 2 行）
- 子どもが打った名前（改行・§ など）が、ログでは `?` に置きかわっていること

## 遠くのチャンクで Minecraft が止まらないことを確かめる手順（手で確かめる）

まだ読み込まれていない遠くの場所を触る命令（置く・読む・埋める・周りをきれいにする）は、メインスレッドで読み込みを待たず、裏で読み込んでから動く。それで Minecraft が止まらないかを、`/debug` で tick を数えて確かめる。地形を作るのが重い、ふつうの地形のワールドで確かめる（スーパーフラットは軽すぎて差が出ない）。

1 回流すと、遠くの地形を 900 チャンクほど作る（ワールドのファイルが増える。「周りをきれいにする」の所は平らになる）。授業のワールドでは流さない。このワールドで `probe_fill.py` も流さない（空の上に山があると削ってしまうため）。

1. 試し用のワールドを新しく作る（ワールドタイプは「デフォルト」、クリエイティブ、チートはオン）
2. ゲームの画面で F3 を押しながら P を押し、チャットに出る知らせを見る。「フォーカスが外れた時にポーズ：無効」（英語なら `Pause on lost focus: disabled`）なら、そのまま進む。「…：有効」と出たら、もう一度押して「無効」にする。**1 回目に出た知らせを覚えておく**（手順 6 で元に戻すため）。ポーズのメニューが開いていないことも確かめる
   - ほかのウィンドウに移ったときにポーズすると、tick が進まないのに時間は進むので、止まっていなくても毎秒の tick が下がって見えるため
   - この設定は、ワールドではなく、その PC の Minecraft の設定（`options.txt`）にすぐ保存される。ワールドを消しても戻らないので、NG のときや途中でやめたときも、手順 6 で元に戻す
3. 下の Python を、別の端末に貼りつけられるようにしておく（`minecraft-mod` フォルダで流す。この README をエディタで開いて写すときは、コードの枠の中だけを写す）。用意ができたら、ゲームのチャットで `/debug start` と打ち、すぐ端末で流す（待っていた時間も数に入り、小さな止まりが薄まって見えなくなるため）
4. チャットに「周囲クリア完了」が出たら（Mac で 1 分ほど）、すぐ `/debug stop` と打つ。次の知らせが出ていたら NG（読み込みが間に合わなかった）
   - 「ばしょの よみこみが まにあわなかったので、…」（ブロックを おけませんでした・うめるのを とちゅうで やめました・まわりを きれいにするのを とちゅうで やめました）
   - 「ばしょを よみこんでいる とちゅうです。…」
5. `/debug stop` でチャットに出る「毎秒 … ティック」が 20 に近ければ（19.5 以上）、止まっていない（直す前の MOD では、遠くを読む・置くだけで毎秒 14 ティックほどに下がった）。`latest.log` に `Can't keep up` が出ていないことも見る
6. ポーズの設定を元に戻す。手順 2 の 1 回目の知らせが「無効」だった（もとから無効）なら、何もしない。「有効」だった（もとは有効）なら、F3 を押しながら P を押し、「…：有効」と出ることを確かめる
7. 試し用のワールドを消す（作った地形の片づけは、これしかない）

2 回目からは `BASE` を 16 の倍数だけ変える（例: 100 万ずつ増やす）。同じ場所は、もう作られていて軽いため。16 の倍数でないと、下の「余りが 8」の形がくずれる。

```bash
python3 -I - <<'EOF'
# 台本の、関数と決まった値の所だけを使う（試験の一覧より前。試験そのものは流さない）
exec(open('tests/websocket/probe_fill.py', encoding='utf-8').read().split('CASES = [')[0])
# 16 で割った余りを 8 にする（「周りをきれいにする」にとって、いちばん重い形。中心が x・z とも余り 8 だと、
# 範囲の外のとなりのチャンクも待つ。読む・置くの 60 か所は、チャンクの端から離れた所なので、となりは待たない）
BASE = 2000008
s = connect()
hello = request(s, 'connect', {'clientId': 'far_check'})
version = ((hello.get('payload') or {}).get('serverInfo') or {}).get('version', '')
if not str(version).startswith(EXPECTED_VERSION):
    sys.exit('MOD の版が %r です。新しくビルドした jar を入れてください' % (version,))
print('x=%d あたりの遠くを読み・置き・埋め、(%d, %d) のまわり 200 マスを平らにします。'
      '5 秒後に始めます（試し用のワールドでなければ Ctrl+C で止めてください）' % (BASE, BASE, BASE + 3008))
time.sleep(5)
ok = lambda reply: (reply.get('payload') or {}).get('success') is True
bad = 0
for i in range(60):
    bad += not ok(get_block_type(s, BASE + i * 16, 40, BASE))
    bad += not ok(set_block(s, BASE + i * 16, 200, BASE + 1008, 'air'))
bad += not ok(fill(s, BASE, 200, BASE + 2008, BASE + 40, 200, BASE + 2048, 'air'))
cleared = clear_area(s, BASE, BASE + 3008)
print('断られた命令: %d 件（0 件のはず）。「周りをきれいにする」の受付: %s（True のはず）' % (bad, ok(cleared)))
EOF
```

## 持ち物を空にする・足元のブロックを確かめる手順（手で確かめる）

忍者屋敷ステージで使う 2 つの命令を、試し用のスーパーフラットのワールド（クリエイティブ、チートはオン）で確かめる。命令は、`minecraft-mod` フォルダで次のように 1 つずつ送る（`ACTION` を `clearInventory` か `getBlockUnderPlayer` にする）。

```bash
python3 -I - <<'EOF'
exec(open('tests/websocket/probe_fill.py', encoding='utf-8').read().split('CASES = [')[0])
ACTION = 'getBlockUnderPlayer'
print(request(connect(), 'command', {'action': ACTION, 'params': {}}))
EOF
```

**持ち物を空にする**（アドベンチャーのときだけ消す。消すのは手・防具・左手も含めて持ち物の全部なので、大事な物は持たずに確かめる）

1. `/give @s minecraft:stone 1` と `/give @s minecraft:iron_helmet 1` で持ち物を入れ、ヘルメットをかぶる。`/gamemode survival` にして `clearInventory` を送る → 持ち物は残り、チャットに「もちものを からっぽに できるのは、アドベンチャーの ときだけです」が出る
2. `/gamemode adventure` にして `clearInventory` を送る → 石もヘルメットも消え、チャットに「持ち物を空にしました」が出る
3. もう一度送る → 何も出ない（消す物が無いときは知らせない）。`/gamemode creative` に戻す

**足元のブロック**（返事の `blockType` と `position` を見る。`position` は Minecraft の座標）

1. ふつうのブロックの上に立つ → そのブロック（例: スーパーフラットの地面なら `grass_block`、y=-61）
2. `/setblock ~ ~ ~2 minecraft:oak_fence` で 2 マス南（+Z）にフェンスを置き、クリエイティブで飛んで、その上に降りる（フェンスは高さ 1.5 なので、ジャンプでは乗れない）→ `oak_fence`（前の MOD は、上の空気を答えた）
3. ブロックの角に、体が半分はみ出すように立つ（スニークで端まで寄る）→ 乗っているブロック（前の MOD は、体のまん中の下のマスを答えた）
4. クリエイティブで飛んで、空中に止まっている間に送る → `air`（命令は別の端末から送るので、ジャンプの間に送るのはむずかしい）。水に入って泳ぐ → `water`
5. `/tp @s 50000 -60 50000` で遠くの地面の上へテレポートした直後に送る → 少し待ってから、着いた所の足元（`grass_block`）が返る（Minecraft は止まらない。`latest.log` に `Can't keep up` が出ない）。テレポートする前に F3 で今の座標を見ておき、終わったら `/tp` でそこへ戻る

**命令を続けて送ったときの順番**（返事を待たずに続けて送る。Scratch のブロックも返事を待たずに送るため）

この手順も、試し用のスーパーフラットのワールドで流す（空の高い所 x・z -150〜-87、y 200〜263 を石で埋めてから空気で消すので、そこに建てた物は消える。probe_fill.py の箱とは重ならない）。`/give @s minecraft:stone 1` で石を 1 つ持ち（持ち物は全部消えるので、大事な物は持たない）、クリエイティブで地面に立ってから（空を飛んでいると、アドベンチャーにしたときに落ちる）、`minecraft-mod` フォルダで次を流す。終わると（Ctrl+C で止めても）、つなぎ直して、置いた石を消し、クリエイティブに戻して、はじめの場所へ戻る。片づけが終わらなかったときは、手で打つ命令が出る。端末のウィンドウを閉じたときは片づけが動かず、受け付けた「埋める」は MOD の中で最後まで動くので、石が増えなくなってから、上の箱を `/fill -150 200 -150 -87 207 -87 minecraft:air` のように高さ 8 段ずつ（y 200〜263 を 8 回。`/fill` は 1 回 32,768 ブロックまで）空気で埋め、`/gamemode creative` に戻す。

```bash
python3 -I - <<'EOF'
import time
exec(open('tests/websocket/probe_fill.py', encoding='utf-8').read().split('CASES = [')[0])


def result(reply):
    """返事の result（失敗の返事には無いので None）"""
    return (reply.get('payload') or {}).get('result')


s = connect()
start = get_position(s)
x, y, z = int(start['x']), int(start['y']), int(start['z'])
(X1, Y1, Z1), (X2, Y2, Z2) = BOX = ((-150, 200, -150), (-87, 263, -87))  # 64×64×64 の石
try:
    # 1. テレポートの直後に 1 回だけ今いる場所を聞く → 列に並ぶので、新しい場所と queued: True
    ids = [send_only(s, 'command', {'action': 'teleport', 'params': {'x': x + 5.5, 'y': y, 'z': z + 0.5}}),
           send_only(s, 'command', {'action': 'getPosition', 'params': {}})]
    print('1. 今いる場所:', result(collect(s, ids)[1]), '（x が', x + 5.5, 'で queued が True なら よい）')
    # 2a. 列が空のときに足元を聞く → 列を追い越して読むので queued: False（列に並ぶ読み方なら、空の列では True になる）
    #     列が空かないと、列に並ぶ読み方でも混んでいて追い越すので False になり、確かめにならない。そのときは止める
    if not wait_queue(s, 60):
        raise SystemExit('2a. 列が 60 秒で空かなかったので、確かめにならない（ほかの命令を止めてから、やり直す）')
    print('2a. 足元（列が空）:', result(request(s, 'command', {'action': 'getBlockUnderPlayer', 'params': {}})),
          '（queued が False なら よい）')
    # 2b. 大きく埋めてすぐ足元を聞く → 埋め終わりを待たずに queued: False
    #     （「埋める」が断られると確かめにならないので、両方の返事を受け取って、埋めるが受け付けられたかも見る）
    t = time.time()
    ids = [send_only(s, 'command', {'action': 'fillBlocks', 'params': {'from': {'x': X1, 'y': Y1, 'z': Z1},
               'to': {'x': X2, 'y': Y2, 'z': Z2}, 'blockType': 'stone'}}),
           send_only(s, 'command', {'action': 'getBlockUnderPlayer', 'params': {}})]
    got = {}
    while len(got) < 2:
        op, data = read_text(s)
        reply = json.loads(data.decode('utf-8')) if op == 1 else {}
        if reply.get('requestId') in ids:
            got[reply['requestId']] = (reply, time.time() - t)
    filled = (got[ids[0]][0].get('payload') or {}).get('success') is True
    under, seconds = got[ids[1]]
    print('2b. 埋める:', '受け付けた' if filled else '断られた（確かめにならないので、やり直す）',
          ' 足元:', result(under), '%.2f 秒' % seconds, '（queued が False で 1 秒より短ければ よい）')
    wait_queue(s, 120)
    # 3. 「アドベンチャーにする → 持ち物を空にする」を続けて送る → 列の順に動くので、石が消えて「持ち物を空にしました」
    #    「サバイバルにする → 持ち物を空にする」を続けて送る → 消さずに「…アドベンチャーの ときだけです」
    for mode in ('adventure', 'survival'):
        ids = [send_only(s, 'command', {'action': 'setGameMode', 'params': {'mode': mode}}),
               send_only(s, 'command', {'action': 'clearInventory', 'params': {}})]
        collect(s, ids)
        time.sleep(1)
    print('3. チャットを見る（上から「持ち物を空にしました」「…アドベンチャーの ときだけです」なら よい）')
finally:
    # Ctrl+C などで止めても、石を消し、クリエイティブに戻し、はじめの場所へ戻す。
    # 前の接続は読みかけの返事が残っていることがあるので、つなぎ直して片づける
    done = False
    try:
        c = connect()
        c.settimeout(120)
        cleared = (fill(c, X1, Y1, Z1, X2, Y2, Z2, 'air').get('payload') or {}).get('success') is True
        request(c, 'command', {'action': 'setGameMode', 'params': {'mode': 'creative'}})
        done = cleared and wait_queue(c, 120) and return_to_start(c, start)
    except BaseException as e:
        # 片づけの間の 2 回目の Ctrl+C も受け止めて、下の案内を出す
        print('あとかたづけが とちゅうで止まった:', repr(e))
    if done:
        print('あとかたづけ: 石を消し、クリエイティブに戻し、はじめの場所へ戻した')
    else:
        print('あとかたづけが終わっていないかもしれない。石が増えなくなってから、チャットで次を打つ:')
        for y0 in range(Y1, Y2 + 1, 8):
            # /fill は 1 回 32,768 ブロックまでなので、高さ 8 段（64×64×8）ずつ消す
            print('  /fill %d %d %d %d %d %d minecraft:air' % (X1, y0, Z1, X2, y0 + 7, Z2))
        print('  /gamemode creative')
        print('  /tp @s %.2f %.2f %.2f' % (start['x'], start['y'], start['z']))
EOF
```

## Scratch で出した生き物が作品を壊さないことを確かめる手順（手で確かめる）

summonEntity で出した生き物には印（`minecraftedu_summoned`）が付く。その生き物と、それが撃った弾・生んだ子ども・変身した先は、ブロックを壊さず火もつけず、爆発や弾で額縁・絵・防具立て・TNT 付きトロッコを壊さない（`SummonedEntityGuard`）。プレイヤーや生き物へのダメージはそのまま。アレイ・ピグリン・村人は、物を拾う・物々交換・畑仕事ができるように外している（村人は畑の育った作物を刈って植え直す。畑の土を踏み荒らすのは止める）。弾そのもの（矢・雪玉・火の玉など）は出さない。この版より前の MOD で出した生き物には印が無く、自然の生き物と同じく壊す。

試し用のスーパーフラットのワールド（クリエイティブ、チートはオン、難易度はピースフル以外、`/entityspawn allow`）で、地面に立って東（+X）を向いて確かめる。「学習準備」を押すと生き物を出せない設定になるので、押したら `/entityspawn allow` で戻す。石の壁は `/fill ~10 ~ ~-4 ~10 ~4 ~4 minecraft:stone` で 10 マス東に作る。生き物は、`minecraft-mod` フォルダで次のように出す（`NAME` と、今いる場所から東・上・南へのずれ `DX`・`DY`・`DZ`）。

```bash
python3 -I - <<'EOF'
import math
exec(open('tests/websocket/probe_fill.py', encoding='utf-8').read().split('CASES = [')[0])
NAME, DX, DY, DZ = 'creeper', 9, 0, 0
s = connect()
p = get_position(s)
print(summon(s, math.floor(p['x']) + DX + 0.5, round(p['y']) + DY, math.floor(p['z']) + DZ + 0.5, 'minecraft:' + NAME))
EOF
```

1. **クリーパー**: 壁を作り、そばに飾りを置く（`/summon armor_stand ~9 ~ ~-2`、`/summon tnt_minecart ~9 ~ ~2`、壁に額縁 `/summon item_frame ~9 ~1 ~ {Facing:4b}`）。`creeper`・`9`・`0`・`0` で出し、`/give @s minecraft:flint_and_steel` の火打ち石を持ってクリーパーを右クリックし（Mac のトラックパッドは 2 本指でクリックか、control を押しながらクリック）、離れる → 爆発しても、壁にも地面にも穴があかず、防具立て・TNT 付きトロッコ・額縁が残る（トロッコに火もつかない）。くらべに `/summon creeper ~9 ~ ~3` で出したクリーパーに火をつける → 穴があく（これはふつうの動き。飾りも壊れ、トロッコも爆発する）。穴は、壁を作ったときと同じ場所に立って `/fill ~4 ~-3 ~-6 ~14 ~-2 ~6 minecraft:dirt replace minecraft:air` と `/fill ~4 ~-1 ~-6 ~14 ~-1 ~6 minecraft:grass_block replace minecraft:air` で埋める
2. **ガスト（撃たせる）**: ガストは高さの差が 4 マス以内で、見えているプレイヤーしかねらわないので、`ghast`・`12`・`3`・`10` で壁の横に出す。`/effect give @s resistance 600 4 true` と `/effect give @s fire_resistance 600 0 true` でダメージを受けないようにしてから `/gamemode survival` にする → 火の玉が当たっても、穴があかず火もつかない。終わったら `/gamemode creative` に戻し、`/kill @e[type=minecraft:ghast]` で消す
3. **打ち返された・撃ったものがいない火の玉**（手で打ち返すのはむずかしいので、持ち主のいない印付きの火の玉を落として確かめる。`power` は 1.20.1 の書き方で、1.20.5 からは名前が変わる。壁を作ったときと同じ場所に立って打つ）
   - `/setblock ~6 ~ ~ minecraft:tnt` で TNT を置き、`/summon fireball ~6 ~6 ~ {Tags:["minecraftedu_summoned"],power:[0.0,-0.1,0.0]}` で真上から落とす → TNT に火がつかず、穴も火もない
   - `/summon armor_stand ~6 ~ ~-3` で防具立てを置き、`/summon fireball ~6 ~6 ~-3 {Tags:["minecraftedu_summoned"],power:[0.0,-0.1,0.0]}` → 防具立てが残る（火の玉は当たって消える）
   - `/summon small_fireball ~6 ~6 ~3 {Tags:["minecraftedu_summoned"],power:[0.0,-0.1,0.0]}` → 火がつかない
   - 生き物へのダメージは残る: `/summon iron_golem ~6 ~ ~-6 {NoAI:1b}` で動かないアイアンゴーレムを置き、`/data get entity @e[type=minecraft:iron_golem,limit=1,sort=nearest] Health` で体力を見る（100.0）。`/summon fireball ~6 ~6 ~-6 {Tags:["minecraftedu_summoned"],power:[0.0,-0.1,0.0]}` を落としてから、もう一度体力を見る → 減っている。終わったら `/kill @e[type=minecraft:iron_golem]`
   - くらべの前に、1 つ目の TNT を `/setblock ~6 ~ ~ minecraft:air` で消す（くらべの爆発で火が移らないように）。くらべに `/setblock ~6 ~ ~6 minecraft:tnt` と `/summon fireball ~6 ~6 ~6 {power:[0.0,-0.1,0.0]}`（印なし）→ TNT に火がついて爆発し、穴があく（ふつうの動き）。穴は、同じ場所に立って `/fill ~1 ~-3 ~1 ~12 ~-2 ~12 minecraft:dirt replace minecraft:air` と `/fill ~1 ~-1 ~1 ~12 ~-1 ~12 minecraft:grass_block replace minecraft:air` で埋める
4. **変身した先**: `zombie`・`4`・`0`・`0` で出し、`/data merge entity @e[type=minecraft:zombie,limit=1,sort=nearest] {DrownedConversionTime:1}` でドラウンドに変える。`/data get entity @e[type=minecraft:drowned,limit=1,sort=nearest] Tags` → `["minecraftedu_summoned"]` が出る。終わったら `/kill @e[type=minecraft:drowned]`
5. **生まれた子ども**: `sheep`・`4`・`0`・`-1` と `sheep`・`4`・`0`・`1` で 2 匹出し、`/give @s minecraft:wheat 2` の小麦を 1 匹ずつにあげる（右クリック）→ 子ヒツジが生まれる。`/execute as @e[type=minecraft:sheep,distance=..10] run data get entity @s Tags` → 3 匹とも `["minecraftedu_summoned"]` が出る。終わったら `/kill @e[type=minecraft:sheep]`
6. **入り直したあと**: `creeper`・`9`・`0`・`0` で出し、`/data get entity @e[type=minecraft:creeper,limit=1,sort=nearest] Tags` → `["minecraftedu_summoned"]` が出る。ワールドを保存して入り直し、もう一度同じ命令 → 同じく出る。壁を作り直して火をつける → 穴があかない
7. 片づけ: 先に `/kill @e[type=minecraft:armor_stand]`・`/kill @e[type=minecraft:tnt_minecart]`・`/kill @e[type=minecraft:item_frame]` で飾りを消す（壁を先に消すと、額縁がアイテムになって落ちる）。それから `/fill ~4 ~ ~-6 ~14 ~6 ~6 minecraft:air` で壁を空気にし（壁を作ったときと同じ場所に立って打つ）、落ちたアイテムを `/kill @e[type=minecraft:item,distance=..20]` で消す。穴は 1 の命令で埋める

**印では止められないもの**（Minecraft が Forge に聞かずに決めるので、この MOD では止めない。どれも起きにくい）: 出したボートがスイレンの葉を壊す、ラヴェジャーがウツボカズラの作物を壊す、燃えている生き物が粉雪を溶かす、スケルトンが粉雪でストレイに変わったときに印が写らない（ストレイはブロックを壊さない）。

## ポートが使われているときの知らせを確かめる手順

MOD の受け口（ポート 14711）をほかのアプリが使っていると、MOD は Scratch とつなげません。そのとき、ワールドに入った人のチャットに知らせが出るかを確かめます。

1. Minecraft のワールドを閉じる（タイトル画面に戻るか、Minecraft を終わる）
2. 別の端末で、ポート 14711 をふさぐ（Windows では `python3` の代わりに `py`）

   ```bash
   python3 -I -c "import socket,time;s=socket.socket(socket.AF_INET6);s.setsockopt(socket.IPPROTO_IPV6,socket.IPV6_V6ONLY,0);s.bind(('::',14711));s.listen();time.sleep(600)"
   ```

3. ワールドに入る。チャットに「Scratch と つなげません（ポート 14711 ばんを ひらけませんでした。Minecraft が 2 つ ひらいていないか たしかめてね）」が出ることを確かめる
4. 2 の端末で Ctrl+C を押してふさぐのをやめ、ワールドを閉じてから入り直す。今度は知らせが出ず、Scratch からつながることを確かめる

## Windows で、ffmpeg が無いときの録画の知らせを確かめる手順（手で確かめる）

録画は Windows だけで動きます。ffmpeg が入っていない（PATH に無い）Windows で、録画を始められないときのログが増えすぎないかを確かめます。

1. ffmpeg の入っていない Windows で、MOD を入れた Minecraft のワールドに入る
2. Scratch の「録画をはじめる」を、60 秒以内に 3 回くり返す
3. `%APPDATA%\.minecraft\logs\latest.log` で、`録画開始エラー` の ERROR（スタックトレース付き）が 1 回だけ、`録画エラー[FFMPEG_MISSING]` の WARN が 1 行だけであることを確かめる（2 回目からは debug.log にだけ出る）
4. 61 秒たってからもう 1 回くり返すと、ERROR と WARN がまた 1 回ずつ出る

## 縦スラブを回す・裏返すときの向きを確かめる手順（手で確かめる）

ストラクチャーブロックや `/place template` で建物を回したり裏返したりして写すとき、縦スラブの向きもいっしょに変わるかを確かめます（変わらないと、写した建物の縦スラブだけ向きがずれる）。試し用のワールド（チートあり）で行います。

1. 空の上などの何もない所に、向きの違う縦スラブを 4 つ並べて置く。写したあとでどれがどれか分かるように、向きごとに木の種類を変える（写すと、並ぶ場所も回ったり逆の順になったりするので、置き場所では見分けられないため）

   | 木の種類 | 置く向き | Scratch から置くときの名前 |
   |---|---|---|
   | オーク | 北向き | `minecraftedu:vertical_oak_slab[facing=north]` |
   | シラカバ | 東向き | `minecraftedu:vertical_birch_slab[facing=east]` |
   | マツ（spruce） | 南向き | `minecraftedu:vertical_spruce_slab[facing=south]` |
   | ジャングル | 西向き | `minecraftedu:vertical_jungle_slab[facing=west]` |

2. ストラクチャーブロック（`/give @s minecraft:structure_block`）の「保存」で、4 つを 1 つの構造物として保存する（名前は例えば `edu_slab_test`）
3. チャットで、別々の場所に向きを変えて写す（`X Y Z` は場所ごとに変えた、空いている場所）

   ```
   /place template minecraft:edu_slab_test X Y Z clockwise_90 none
   /place template minecraft:edu_slab_test X Y Z 180 none
   /place template minecraft:edu_slab_test X Y Z counterclockwise_90 none
   /place template minecraft:edu_slab_test X Y Z none left_right
   /place template minecraft:edu_slab_test X Y Z none front_back
   ```

4. F3 を押して、写した縦スラブを 1 つずつ見て、画面の右の `facing` を確かめる（木の種類で、もとのどれかを見分ける）

| 写し方 | オーク（もとは北）・シラカバ（東）・マツ（南）・ジャングル（西）が、それぞれ |
|---|---|
| 時計回りに 90 度（`clockwise_90`） | 東・南・西・北 |
| 180 度（`180`） | 南・西・北・東 |
| 反時計回りに 90 度（`counterclockwise_90`） | 西・北・東・南 |
| 左右に裏返す（`left_right`） | 南・東・北・西（北と南だけ入れかわる） |
| 前後に裏返す（`front_back`） | 北・西・南・東（東と西だけ入れかわる） |

5. 見た目（板の側）と、選んだときの枠（黒い線）が同じ側にあることも見る
