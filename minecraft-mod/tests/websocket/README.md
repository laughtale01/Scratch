# WebSocket の受け口の試験

`src/main/java/com/github/minecraftedu/network/SimpleWebSocketServer.java` を、Minecraft を起動せずに確かめる試験です。
Minecraft の部品（`MinecraftServer`・`CommandExecutor`・`MinecraftWebSocketHandler`・ロガー）は `stubs/` の偽物に差し替え、
本物の `SimpleWebSocketServer.java` をそのままコンパイルして動かし、Python から接続を送ります。

## 流し方

```bash
cd minecraft-mod
mise exec -- bash tests/websocket/run.sh
```

- Java 17（`mise.toml` の temurin-17）と python3 が要ります。
- 試験用のポートは 24711 です（本物の MOD の 14711 とぶつからないように）。変えるときは `WS_TEST_PORT=24800` を付けます。
- 2 分ほどかかります（時間切れの確かめで数秒ずつ待つのと、ログの間引きの確かめで 60 秒待つため）。
- MOD のビルド（`./gradlew build`）には含まれません。

## 確かめていること

- つないでよいサイト（Origin）: `https://laughtale01.github.io` と `http://localhost:8000`・`http://127.0.0.1:8000` だけ。無い・ほかのサイトは 403
- 自分の PC 以外（LAN のアドレス）からの接続はすぐ切る（Mac のときだけ確かめる）。IPv6 の `::1` からはつながる
- ヘッダーの上限（1 行 8KB・100 行）ですぐ切る。ハンドシェイクの締め切り（受け付けてから 5 秒。少しずつ送っても延びない）
- ハンドシェイクと最初のフレームが 1 回で届いても、フレームを取りこぼさない
- マスクの無いフレーム、1MB を超えるフレーム、125 バイトを超える制御フレームは切る。Ping には正しい長さの Pong を返す
- 同時接続は 8 本まで。断った接続・切れた接続のあとも枠が戻り、余計にも増えない
- ログ: 受け取った全文を出さない、断った Origin は見える ASCII 以外を `?` にして 100 文字ほどに切る、断った接続のログは理由の種類ごとに 60 秒に 1 行まで（鍵のないリクエスト・長い URL・ハンドシェイクの途中で切られた接続・時間切れも。くり返してもログ全体が DEBUG も含めて増えないことを数える。60 秒たつと間に断った数を書いて 1 行出る）、つながった接続が切れたら info で出す
- 決まりに合わないフレーム（マスクなし・大きすぎる）のログは、くり返しても 1 行だけ。つないだあとに乱暴に切られても ERROR を出さない

## 確かめていないこと（試験の外）

- `MinecraftWebSocketHandler` と `CommandExecutor` は偽物なので、命令の中身（断ったときのチャットやログ）はこの試験では確かめていない（受け取った全文がログに出ないことは、本物の `SimpleWebSocketServer` で、この試験が確かめている）
- 受付のループで Error が起きたときの片付け（枠を返して閉じる）と、失敗が続いたときの 100ms の待ち
- 停止（stop）の途中に来た接続の片付け
- Windows での動き（この試験は Mac で作った）
- `CommandExecutor` の中身（座標と範囲の上限、名前の打ちまちがい、キーや params が無いとき、消した入口（query の受け口・getBlock の命令）が残っていないこと、チャットの長さと見えない文字、断ったときのチャットとその間引き）。下の手順で、本物の MOD で確かめる
- 下の手順でも出せないチャット: 「MOD の なかで まちがいが おきました（せんせいに しらせてね）」（MOD の不具合のときだけ）、「いま まわりを きれいにしている とちゅうです。おわるまで まってね」（「周りをきれいにする」を動かす必要がある）、「いまは いきものを だせない せっていです」（先生が `/entityspawn deny` にしたとき）
- MOD の受け口を開けなかったときの知らせ。下の「ポートが使われているときの知らせを確かめる手順」で確かめる

## 本物の MOD で上限と、断ったときのチャットを確かめる手順

**必ず新しく作った試し用のワールドで行ってください。授業で使うワールド（生徒の作品があるワールド）では行わないでください。**
「周りをきれいにする」などを間違えて動かすと、作品が消えて元に戻せません。

Scratch（gui.js）は体積を先に確かめて断るので、Scratch のブロックからでは MOD 側の確かめまで届かない場合があります。
そのため、命令を MOD へ直接送るスクリプト `probe_fill.py` で確かめます。

1. MOD を新しくビルドして入れ直す（古い MOD のままだと、古い MOD を確かめてしまう）
   - mods フォルダに前の jar（`minecraftedu-mod-0.1.0-1.20.1.jar` や `minecraftedu-mod-0.1.0.jar` など）があれば、先に外す（同じ MOD が 2 つあると、正しく読み込めない）

   ```bash
   cd minecraft-mod
   ./gradlew build
   # build/libs/ にできた jar（minecraftedu-mod-0.2.0-1.20.1.jar。版は build.gradle の version）を Minecraft の mods フォルダにコピーし、Minecraft を起動し直す
   ```

2. Minecraft で、新しく作った試し用の**スーパーフラット**のワールドを開く（ふつうのワールドでは流さない。山の頂上などがあると、空気で削れる）
   - **オーバーワールド**（ネザーやエンドではない）にいて、**クリエイティブ**にしておく（y=-60 へテレポートするので、ネザーでは奈落に落ちる。また古い MOD に流すと、ワールドの外へテレポートしてしまうことがあるため）
   - 生き物を出すのを止めていたら、チャットで `/entityspawn allow` と打って許可しておく（止めたままだと、生き物の名前の打ちまちがいの件が「いきものを だせない せってい」になって NG で止まる）
3. Minecraft と同じ PC の別の端末で、次を実行する（試し用のワールドか聞かれるので、`yes` と入力する。Windows では `python3` の代わりに `py` を使う）

   ```bash
   cd minecraft-mod
   python3 -I tests/websocket/probe_fill.py
   ```

   - このスクリプトは、ランチャーで起動した Minecraft（mods フォルダに jar を入れたもの）に向けて流す。開発用の起動（`./gradlew runClient`）では MOD の版が `0.0NONE` になるので、版の確かめで止まる

4. 画面に、それぞれの命令の結果（ok / NG）が出る。チャットを確かめる命令（断られる命令、入れ物の件、チャットの件）のたびにスクリプトが止まるので、ゲームのチャットで「[probe] N 件目」の行のすぐ下に下の表の文が出たかを見て、出たら `y` と入力する（同じ文が続くので、番号の行で前の命令の文と見分ける）
   - はじめに、接続の返事で MOD の版（0.2.0…）と最大の接続数（8）を確かめる。違えば、ワールドに命令を送る前に止まる
   - 大きな「ブロックで埋める」のあとは、Minecraft が置き終わるまでチャットに出ないことがある。出るまで待ってから答える
   - 途中でプレイヤーを x=1000, y=-60, z=0 へテレポートする（相対座標の確かめのため）。終わったら（NG で止まったときも）元の場所へ戻す
   - はじめに元の場所の座標を表示する。ゲームが落ちたなどで戻せなかったときは「/tp @s x y z で戻ってください」と表示するので、そのとおりに打って戻る
   - 返事だけでは断った理由が分からない（ほかの理由で断られても同じ返事になる）ので、チャットの文で確かめる
   - 問いの文が「=」で始まるときは、番号の行のすぐ下の行が、ちょうどその文（それより長くも短くもない）かを見る（チャットの長さの確かめ）
   - 期待と違う結果が 1 件でも出たら、そこで止まる。NG のときは、まず mods フォルダの jar が新しくビルドしたもの 1 つだけかを確かめる
5. 最後に、失敗のチャットの間引きを 8 件確かめる。「[probe] 間引き N」と「[probe] 間引き N おわり」の 2 つの行のあいだに、下の表の文が上から順に、それだけ出たかを見て、そうなら `y` と入力する

| 送る命令（番号の行をはさまずに続けて送る） | 2 つの行のあいだに出るはずの文 |
|---|---|
| ブロックを置く、x が回り込む数を 5 回 | 「ばしょがワールドの外です」だけ |
| ブロックを置く（x が回り込む数）と、ブロックで埋める（x が回り込む数）を、かわりばんこに 3 回ずつ | 「ばしょがワールドの外です」「はんいがワールドの外です」だけ |
| ブロックで埋める、名前を変えながら打ちまちがいを 5 回 | 「その ブロックの なまえが ちがいます: minecraft:no_such_0」だけ |
| ブロックを置く、x が回り込む数を 1 回、（Minecraft がそこまで出し終わるのを待ってから）3.5 秒まって、もう 1 回 | 「ばしょがワールドの外です」「ばしょがワールドの外です」（3 秒たつと、また出る） |
| ブロックを置く、x が回り込む数を 1 回、ふつうのチャット「probe ふつうの チャット」、すぐもう 1 回 | 「ばしょがワールドの外です」「probe ふつうの チャット」「ばしょがワールドの外です」（間にほかのチャットが出ると、すぐまた出る） |
| ブロックを置く、x が回り込む数を 1 回、時刻を正午にする、すぐもう 1 回 | 「ばしょがワールドの外です」「時刻: 正午」「ばしょがワールドの外です」 |
| ブロックを置く、x が回り込む数を 1 回、y=-64 のブロックの種類を調べる、すぐもう 1 回 | 「ばしょがワールドの外です」「岩盤」（英語の設定なら「Bedrock」）「ばしょがワールドの外です」 |
| 入れ物が無い所にアイテムを入れる、ふつうのチャット、もう 1 回（返事を待たずに 3 つ続けて送り、あとで返事をまとめて受け取る） | 「そこに いれものが ありません」「probe ふつうの チャット」「そこに いれものが ありません」（出る順がそのまま） |

同じ種類の失敗は 3 秒に 1 回だけチャットに出る（「ずっと」の中で失敗が続いても、チャットが流れないように）。間にほかのチャットが出たら、すぐまた出る。

座標は Minecraft の座標（F3 で出るもの）です。Scratch のブロックの Y は、これより 60 大きくなります（Minecraft の y=300 は Scratch の y=360）。

| 飛ぶ速さ、倍率のキーが無い | 断られる | 「うまく できませんでした（いれた あたいを たしかめてね）」 |
| ブロックを置く、ブロックの名前が無い | 断られる | 「うまく できませんでした（いれた あたいを たしかめてね）」 |

- 「成功」の命令は、空の上（y=200 以上）に空気を置く、一番下の岩盤に岩盤を置く、空の上にチェストを置いて消す、入れ物にアイテムを入れる（入れ物が無い所か、範囲の外のスロットなので何も入らない）、プレイヤーをテレポートする、時刻を正午にする、チャットに文を出す、今いる位置・見ているブロック・ブロックの種類を調べる、だけです。スーパーフラットのワールドなら見た目は変わらず、プレイヤーも最後に元の場所へ戻ります。チェストは、消したあとにその場所が空気になったかを調べて確かめます。途中で止まったときも消します（消せなかったときは、`/setblock 2 300 2 air` と打つように表示します）。
- 「周りをきれいにする」「生き物を全部消す」のふつうの動き（中心から 200 マスを平らにする・生き物を消す）は、このスクリプトでは試しません。試すときも試し用のワールドで行ってください。


## ログの確かめ（任意）

`probe_fill.py` のあとに、Minecraft のログで、失敗のログが増えすぎていないかを確かめる（Mac は `~/Library/Application Support/minecraft/logs/`、Windows は `%APPDATA%\.minecraft\logs\`）。

- `latest.log` の `WARN` の行が、失敗の種類ごとに 1 行だけ（60 秒のあいだ）であること。2 回目からは `debug.log` にだけ出る
- 「MOD が知らない命令」と「ブロックを調べる（getBlock）の命令」の件は同じ間引きに入り、`Unknown command: noSuchCommand` の WARN 1 行であること（ただし 60 秒より長くかけて答えたときは、`Unknown command: getBlock` の行がもう 1 行出てよい）
- 「params が無い」の件が `Command without params: clearArea` の WARN 1 行であること。「中心のキーが無い」の件が `Bad command parameters: clearArea (MissingParameterException: …)` の WARN 1 行であること。「x が無い」の件が `Bad command parameters: teleport (MissingParameterException: missing parameter)` の WARN 1 行であること
- 「知らないプロパティが 2 つ」の件が、`Unknown property '…' for block air (2 unknown properties)` の 1 行にまとまっていること（DEBUG も含めて、1 回の命令で 1 行）
- 「座標が数でない」と「ブロックの名前が無い」の件が、`Bad command parameters: setBlock (UnsupportedOperationException: …)` と `Bad command parameters: setBlock (NullPointerException: …)` の WARN 1 行ずつで、スタックトレース（`at com.github…` の行）が付いていないこと（同じ命令でも、例外の種類ごとに 1 行）
- 子どもが打った名前（改行・§ など）が、ログでは `?` に置きかわっていること

## ポートが使われているときの知らせを確かめる手順

MOD の受け口（ポート 14711）をほかのアプリが使っていると、MOD は Scratch とつなげません。そのとき、ワールドに入った人のチャットに知らせが出るかを確かめます。

1. Minecraft のワールドを閉じる（タイトル画面に戻るか、Minecraft を終わる）
2. 別の端末で、ポート 14711 をふさぐ（Windows では `python3` の代わりに `py`）

   ```bash
   python3 -I -c "import socket,time;s=socket.socket(socket.AF_INET6);s.setsockopt(socket.IPPROTO_IPV6,socket.IPV6_V6ONLY,0);s.bind(('::',14711));s.listen();time.sleep(600)"
   ```

3. ワールドに入る。チャットに「Scratch と つなげません（ポート 14711 ばんを ひらけませんでした。Minecraft が 2 つ ひらいていないか たしかめてね）」が出ることを確かめる
4. 2 の端末で Ctrl+C を押してふさぐのをやめ、ワールドを閉じてから入り直す。今度は知らせが出ず、Scratch からつながることを確かめる

## Windows で、ffmpeg が無いときの録画の知らせを確かめる手順（手で確かめる）

録画は Windows だけで動きます。ffmpeg が入っていない（PATH に無い）Windows で、録画を始められないときのログが増えすぎないかを確かめます。

1. ffmpeg の入っていない Windows で、MOD を入れた Minecraft のワールドに入る
2. Scratch の「録画をはじめる」を、60 秒以内に 3 回くり返す
3. `%APPDATA%\.minecraft\logs\latest.log` で、`録画開始エラー` の ERROR（スタックトレース付き）が 1 回だけ、`録画エラー[FFMPEG_MISSING]` の WARN が 1 行だけであることを確かめる（2 回目からは debug.log にだけ出る）
4. 61 秒たってからもう 1 回くり返すと、ERROR と WARN がまた 1 回ずつ出る

## 縦スラブを回す・裏返すときの向きを確かめる手順（手で確かめる）

ストラクチャーブロックや `/place template` で建物を回したり裏返したりして写すとき、縦スラブの向きもいっしょに変わるかを確かめます（変わらないと、写した建物の縦スラブだけ向きがずれる）。試し用のワールド（チートあり）で行います。

1. 空の上などの何もない所に、向きの違う縦スラブを 4 つ並べて置く。写したあとでどれがどれか分かるように、向きごとに木の種類を変える（写すと、並ぶ場所も回ったり逆の順になったりするので、置き場所では見分けられないため）

   | 木の種類 | 置く向き | Scratch から置くときの名前 |
   |---|---|---|
   | オーク | 北向き | `minecraftedu:vertical_oak_slab[facing=north]` |
   | シラカバ | 東向き | `minecraftedu:vertical_birch_slab[facing=east]` |
   | マツ（spruce） | 南向き | `minecraftedu:vertical_spruce_slab[facing=south]` |
   | ジャングル | 西向き | `minecraftedu:vertical_jungle_slab[facing=west]` |

2. ストラクチャーブロック（`/give @s minecraft:structure_block`）の「保存」で、4 つを 1 つの構造物として保存する（名前は例えば `edu_slab_test`）
3. チャットで、別々の場所に向きを変えて写す（`X Y Z` は場所ごとに変えた、空いている場所）

   ```
   /place template minecraft:edu_slab_test X Y Z clockwise_90 none
   /place template minecraft:edu_slab_test X Y Z 180 none
   /place template minecraft:edu_slab_test X Y Z counterclockwise_90 none
   /place template minecraft:edu_slab_test X Y Z none left_right
   /place template minecraft:edu_slab_test X Y Z none front_back
   ```

4. F3 を押して、写した縦スラブを 1 つずつ見て、画面の右の `facing` を確かめる（木の種類で、もとのどれかを見分ける）

| 写し方 | オーク（もとは北）・シラカバ（東）・マツ（南）・ジャングル（西）が、それぞれ |
|---|---|
| 時計回りに 90 度（`clockwise_90`） | 東・南・西・北 |
| 180 度（`180`） | 南・西・北・東 |
| 反時計回りに 90 度（`counterclockwise_90`） | 西・北・東・南 |
| 左右に裏返す（`left_right`） | 南・東・北・西（北と南だけ入れかわる） |
| 前後に裏返す（`front_back`） | 北・西・南・東（東と西だけ入れかわる） |

5. 見た目（板の側）と、選んだときの枠（黒い線）が同じ側にあることも見る
